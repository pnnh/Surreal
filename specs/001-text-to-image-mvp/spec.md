# Feature Specification: 文生图 MVP（对话 + 本地资产收藏）

**Feature Branch**: `001-text-to-image-mvp`

**Created**: 2026-11-08

**Status**: Clarified

**Input**: User description: "初期 MVP：文生图对话界面、文件存储与收藏界面；后端调用 Poe API；早期本地文件系统存储，密钥仅环境变量；为自用游戏美术资产生成铺路。"

## Clarifications

### Session 2026-11-08

- Q: MVP 的模型选择器应从哪里获取可选图像模型列表？ → A: 精简白名单（默认 `GPT-Image-1.5` + 少量备选）；可手动改模型 ID；不依赖启动时拉取全量 Poe 模型目录。
- Q: 系统提示词应按什么作用域保存并生效？ → A: 全局唯一 `GenerationProfile`；所有新生成默认使用；不在 MVP 做会话级覆盖。
- Q: MVP 资产库是否需要支持删除已生成图片（含本地文件）？ → A: 支持；用户确认后删除元数据与本地文件（无回收站）。
- Q: 多轮对话出图时，发给 Poe 的上下文应包含哪些内容？ → A: 全局系统提示词 + 当前用户提示词 + 本会话最近 N 轮（有上限；N 在 plan 中确定）；不发送无限全文历史。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 文生图对话出图 (Priority: P1)

开发者打开 Surreal，选择一个可用的图像生成模型，输入提示词（可选附带系统提示词/风格约束），提交后在同一对话线程中看到生成图片与相关文本回复，并可继续多轮修改提示词再生成。

**Why this priority**: 没有稳定出图能力，产品无核心价值。

**Independent Test**: 配置有效 `POE_API_KEY` 后，仅使用对话页完成「选模型 → 输入提示词 → 得到可显示图片」全流程。

**Acceptance Scenarios**:

1. **Given** 已配置有效 Poe API Key 且网络可用，**When** 用户选择图像模型并发送提示词，**Then** 系统在合理等待后展示至少一张生成图片，并保留该轮用户输入。
2. **Given** 同一会话已有历史消息，**When** 用户发送后续提示词，**Then** 新消息追加到同一会话时间线，不覆盖历史；发往 Poe 的请求包含全局系统提示词、当前提示词及本会话最近 N 轮上下文（有上限）。
3. **Given** Poe 返回失败或余额不足，**When** 用户发送提示词，**Then** 界面展示可读错误信息，不出现未处理崩溃，且不写入损坏的资产记录。

---

### User Story 2 - 生成结果本地落盘 (Priority: P1)

每次成功生成的图片被保存到本地资产存储，并记录提示词、模型、会话关联与时间等元数据，刷新应用后仍可访问。

**Why this priority**: Poe CDN 链接可能过期；自用工作流要求资产可复用。

**Independent Test**: 完成一次成功生成后断开外网或清除仅内存状态，仍能从资产库打开同一文件。

**Acceptance Scenarios**:

1. **Given** 一次成功的文生图，**When** 响应处理完成，**Then** 本地存储中存在对应图像文件，且元数据包含提示词与模型标识。
2. **Given** 应用重启，**When** 用户打开资产库，**Then** 仍能看到此前落盘的图片。

---

### User Story 3 - 资产浏览与收藏 (Priority: P2)

开发者在资产库中浏览已生成图片，可收藏/取消收藏，并可按收藏筛选，便于后续游戏制作时快速找回。

**Why this priority**: 沉淀工作流价值；可在出图稳定后立即交付。

**Independent Test**: 在不发起新生成的情况下，仅操作资产库完成浏览、收藏与筛选。

**Acceptance Scenarios**:

1. **Given** 资产库中有多张图片，**When** 用户标记收藏，**Then** 该资产显示为已收藏且状态持久化。
2. **Given** 存在已收藏与未收藏资产，**When** 用户筛选「仅收藏」，**Then** 列表只显示已收藏项。
3. **Given** 用户取消收藏，**When** 再次打开或刷新筛选，**Then** 该资产不再出现在「仅收藏」结果中。
4. **Given** 资产库中存在某张图片，**When** 用户确认删除，**Then** 该资产从列表消失，对应本地文件被移除，且刷新后不再出现。

---

### User Story 4 - 系统提示词可调 (Priority: P2)

开发者在设置中编辑一份全局系统提示词（风格/题材约束），保存后所有**新的**文生图请求默认携带该提示词，以满足「不像 Ludo 那样锁死提示词」的诉求。MVP 不做按会话覆盖。

**Why this priority**: 差异化核心之一；实现成本低，应纳入 MVP。

**Independent Test**: 在设置页修改并保存全局系统提示词后发起生成，能在请求侧或调试信息中确认新提示词被使用（无需对比像素质量）。

**Acceptance Scenarios**:

1. **Given** 用户在设置中保存了自定义全局系统提示词，**When** 发起新的文生图，**Then** 该全局系统提示词参与本次生成请求。
2. **Given** 用户清空或恢复默认全局系统提示词，**When** 再次生成，**Then** 使用默认行为且不残留已删除自定义内容。
3. **Given** 用户已修改全局系统提示词，**When** 查看历史会话中的旧消息，**Then** 历史记录保持原样（不回溯改写已完成生成）。

---

### Edge Cases

- API Key 未配置或无效时，生成入口给出明确配置指引，不发起无效请求。
- 模型返回文本但无图像附件时，展示说明且不创建空资产。
- 磁盘空间不足或写入失败时，回滚元数据写入并提示失败。
- 超大图片或异常 MIME 类型时，拒绝或安全降级，避免破坏资产库索引。
- 并发多次生成时，资产 ID/文件名不冲突。
- 删除资产时若本地文件已缺失，仍清除元数据并提示部分清理成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供文生图对话界面，支持选择图像生成模型、输入提示词、展示回复与图片。
- **FR-001a**: 可选模型 MUST 来自应用维护的精简白名单；默认模型 MUST 为 `GPT-Image-1.5`；用户 MUST 能从白名单选择或手动输入其它 Poe 模型 ID。MVP MUST NOT 依赖启动时调用 Poe `/v1/models` 拉取全量目录。
- **FR-002**: 系统 MUST 通过 Poe OpenAI 兼容 API 发起生成请求；密钥 MUST 仅从环境变量读取（如 `POE_API_KEY`）。
- **FR-002a**: 每次生成请求 MUST 包含：当前全局系统提示词、当前用户提示词，以及本会话最近 N 轮消息上下文（N 为可配置上限，MVP 默认值在实现计划中确定）。系统 MUST NOT 无上限发送完整会话历史。
- **FR-003**: 系统 MUST 在成功生成后将图像二进制持久化到本地文件系统，并保存可检索元数据（至少：资产 ID、提示词、模型、创建时间、来源会话/消息引用、收藏状态）。
- **FR-004**: 系统 MUST 提供资产库界面，支持浏览缩略图/原图与收藏、取消收藏、按收藏筛选。
- **FR-004a**: 系统 MUST 允许用户在确认后删除资产：移除元数据记录与对应本地图像文件。MVP MUST NOT 实现回收站/软删除恢复。
- **FR-005**: 系统 MUST 提供全局唯一的生成配置（`GenerationProfile`），允许用户查看与编辑其中的系统提示词；所有新生成请求 MUST 默认应用该全局系统提示词。MVP MUST NOT 实现会话级系统提示词覆盖。
- **FR-006**: 系统 MUST 在 Poe 调用失败时返回可读错误，且 MUST NOT 将 API 密钥写入日志或前端。
- **FR-007**: 系统 MUST 将本地数据目录（资产与数据库）排除在版本控制之外；仓库仅可包含无密钥的环境变量示例。
- **FR-008**: 存储访问 MUST 通过可替换抽象，使后续接入 S3 兼容 API 时无需改写对话与收藏业务流程（MVP 仅实现本地后端）。
- **FR-009**: MVP MUST NOT 要求多用户注册登录；默认按单用户本机使用设计。
- **FR-010**: MVP 范围 MUST NOT 包含 3D 网格生成、骨骼绑定或动画时间轴产品功能。

### Key Entities

- **Conversation（会话）**: 一次连续的文生图对话线程，包含有序消息。
- **Message（消息）**: 用户或助手的一条记录；助手消息可关联零个或多个生成资产。
- **Asset（资产）**: 落盘的图像文件及其元数据（提示词、模型、时间、收藏标记、可选缩略图）；可被硬删除。
- **GenerationProfile（生成配置）**: 单用户全局一份；含系统提示词与默认模型等；新生成读取当前值，不回溯修改历史消息。
- **ModelRef（模型引用）**: Poe 图像 bot/模型标识；MVP 以白名单条目为主，允许自定义 ID 覆盖。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 Key 有效且模型可用时，用户可在 3 分钟内完成首次「配置确认 → 出图 → 在对话中看到图」。
- **SC-002**: 成功生成的图片 100% 可在应用重启后从资产库打开（正常关机/重启场景）。
- **SC-003**: 用户可在 1 分钟内完成收藏并筛选出目标资产。
- **SC-003a**: 用户可在确认后删除资产，删除后资产库与磁盘均不再保留该条目（正常路径）。
- **SC-004**: 未配置密钥时，100% 的生成尝试被阻止并给出可操作提示（不以未捕获异常失败）。
- **SC-005**: 仓库扫描不含真实密钥文件；文档说明仅通过环境变量注入机密。

## Assumptions

- 目标用户为开发者本人（单用户、本机或私有部署）。
- 已有可用的 Poe API 订阅/点数；MVP 使用精简白名单（默认 `GPT-Image-1.5`，备选如 `FLUX-pro-1.1`、`Imagen-4`），完整远程模型目录为后续增强。
- 中文 UI 文案可接受；代码与 API 字段使用英文。
- 早期不实现云端多端同步；S3 为后续规格。
- 系统提示词为全局文本配置，暂不做会话覆盖与可视化提示词节点编辑器。
- 多轮上下文窗口大小 N、缩略图生成策略、并发生成限制等实现细节延期到 `/speckit-plan`。
- MVP 不要求参考图/图生图上传（可后续规格增强）。
- AGPL-3.0 许可已选定，对外分发/托管需遵守 AGPL 义务。
- 技术栈倾向：Next.js 全栈（App Router）。
