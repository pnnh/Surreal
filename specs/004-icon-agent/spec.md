# Feature Specification: 生图标 Agent

**Feature Branch**: `004-icon-agent`

**Created**: 2026-11-08

**Status**: Clarified

**Input**: User description: "参考已实现的生图 Agent，实现生图标 Agent：对话多轮反问敲定细节后一次性生成应用/Web 常用尺寸图标（位图为主，透明背景优先）；新建会话可选图片或图标；资产可收藏；资产库增加类型过滤；按会话 ID 分子目录并区分 images/icons；同步 MCP generate_icon。澄清结论：Q1 位图为主不做 SVG；Q2 尺寸列表由对话敲定后批量生成；Q3 可清空旧 data；Q4 含 MCP。"

## Clarifications

### Session 2026-11-08

- Q: 输出形态？ → A: 位图为主（PNG/WebP，透明优先）；SVG 不做（后置）。
- Q: 一次生成哪些尺寸？ → B: Agent 与用户敲定尺寸列表后，按列表批量生成（无固定死包）。
- Q: 资产目录迁移？ → C: 可清空本地 `data/`，按新结构重建。
- Q: 是否含 MCP？ → B: 同步提供 `generate_icon`（直出、无反问，对齐现有 MCP 生图）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新建会话选择图片或图标 (Priority: P1)

开发者新建对话时选择本会话用途：**普通图片**或**图标**。选择图标后，后续澄清与生成均按图标语义进行（尺寸、透明底、用途等），不会与普通生图会话混用同一套默认假设。

**Why this priority**: 入口分流是后续 Agent 与存储分类的前提。

**Independent Test**: 新建会话选「图标」→ 会话列表/会话详情可识别为图标类 → 发送模糊需求进入图标澄清而非普通生图默认话术。

**Acceptance Scenarios**:

1. **Given** 用户点击新建会话，**When** 选择「图标」，**Then** 创建的会话标记为图标类型，对话 UI 呈现图标工作流（含跳过澄清/立即生成等与生图 Agent 对等的门闩控件）。
2. **Given** 用户选择「普通图片」，**When** 创建会话，**Then** 行为保持既有生图 Agent，不受图标逻辑干扰。
3. **Given** 已存在的图标会话，**When** 重新打开，**Then** 仍按图标类型加载，不可在 UI 中静默改成普通图片类型。

---

### User Story 2 - 图标 Agent 反问后批量出图 (Priority: P1)

用户用自然语言描述想要的图标（可很模糊）。文本 Agent 反向拷问关键属性（风格、用途、主色、是否透明底、目标平台等），并与用户敲定**尺寸列表**与建议提示词。用户确认或跳过澄清后，系统按敲定尺寸列表一次性批量生成多张位图图标并展示在同一会话中。

**Why this priority**: 核心价值；无澄清与批量尺寸则本 feature 不成立。

**Independent Test**: 「做个购物车图标」→ 反问并敲定如 16/32/64 → 确认 → 同轮出现对应多张图标，且确认前无生图调用。

**Acceptance Scenarios**:

1. **Given** 用户发送模糊图标需求，**When** Agent 回复，**Then** 含约 2–4 个相关澄清点、建议提示词草案，以及待确认的尺寸列表（或明确请用户确认尺寸），且尚未调用生图模型。
2. **Given** 尺寸列表与提示词已敲定且用户确认（或「立即生成」），**When** 生成完成，**Then** 列表中每个尺寸至少对应一张已落盘图标资产，并出现在会话消息中。
3. **Given** 用户说「直接生成」或点「跳过澄清」，**When** 系统处理，**Then** 基于已有信息合成提示词与尺寸（若尺寸未谈，采用合理默认尺寸集）并批量生成，不再继续反问。

---

### User Story 3 - 收藏与资产库类型过滤 (Priority: P1)

生成的图标可在对话中点击收藏（与现有聊天图片收藏一致）。资产库列表增加**类型**过滤（至少：全部 / 普通图片 / 图标），便于只浏览图标或只浏览图片。

**Why this priority**: 图标与图片并存后，无类型过滤会难以管理。

**Independent Test**: 收藏一张图标 → 资产库选「图标」可见该资产；选「普通图片」不可见。

**Acceptance Scenarios**:

1. **Given** 会话中已生成图标，**When** 用户点击收藏，**Then** 该资产标记为收藏且类型为图标。
2. **Given** 资产库存在图片与图标，**When** 选择类型「图标」，**Then** 列表仅显示图标类资产。
3. **Given** 未选类型或选「全部」，**When** 浏览资产库，**Then** 两类资产均可出现（可带类型标识）。

---

### User Story 4 - 按会话组织的本地资产目录 (Priority: P2)

本地资产落盘按会话组织：以会话 ID 为子目录，其下再分普通图片与图标目录。本 feature 允许清空旧扁平 `data/` 后按新结构写入；不再承诺迁移历史文件。

**Why this priority**: 便于按会话清理与区分资产形态；对自用 MVP 可接受重置。

**Independent Test**: 分别在图片会话与图标会话各生成一次 → 磁盘上可见 `…/<conversationId>/images|icons/…` 结构。

**Acceptance Scenarios**:

1. **Given** 图标会话生成成功，**When** 检查本地数据目录，**Then** 文件位于该会话下的图标子目录，而非全局扁平目录。
2. **Given** 普通图片会话生成成功，**When** 检查本地数据目录，**Then** 文件位于该会话下的图片子目录。
3. **Given** 用户接受清空旧数据，**When** 启用新结构，**Then** 系统不再依赖旧扁平路径作为写入目标。

---

### User Story 5 - MCP 直出图标 (Priority: P2)

外部 Agent（如 Cursor）可通过 MCP 调用 `generate_icon`：传入提示词与尺寸列表（及可选模型），**无反问**，直接批量生成并落盘，归属 MCP 会话，且资产类型为图标。

**Why this priority**: 与现有 MCP 生图对称，便于在 IDE 工作流中取图标；可独立于 Web Agent 验证。

**Independent Test**: 仅调 MCP：`generate_icon` + 提示词 + `[32,64]` → 返回资产信息且文件存在于图标目录。

**Acceptance Scenarios**:

1. **Given** MCP 已配置且密钥有效，**When** 调用 `generate_icon`，**Then** 不经澄清环，按给定（或默认）尺寸批量生成图标并落盘。
2. **Given** 调用成功，**When** 查看会话/资产元数据，**Then** 会话可识别为 MCP 来源，资产类型为图标。
3. **Given** 未配置密钥或参数非法（空提示词、空尺寸且无默认），**When** 调用，**Then** 返回可读错误且不写入半截业务状态（或不留下误导性成功标记）。

---

### Edge Cases

- 尺寸列表为空且用户确认生成：拒绝或回退到文档化的默认尺寸集（如 16/32/64），并在回复中说明假设。
- 单次尺寸数量过大（如 >20）：拒绝或截断并提示，避免过量扣点与超时。
- 模型无法保证透明底：仍请求透明/无底风格；以实际返回为准，UI 不假装一定透明成功。
- 批量中部分尺寸失败：已成功尺寸保留展示；失败尺寸给出可读错误，允许重试失败项（至少整批重试）。
- 未配置 `POE_API_KEY`：阻止 Agent 与生成，提示配置。
- 在普通图片会话误用图标话术：仍按会话类型走对应 Agent，不自动改类型。
- 并发多次「立即生成」：同会话串行或拒绝第二请求。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 新建会话时用户 MUST 能选择会话用途：`image`（普通图片）或 `icon`（图标）；该选择 MUST 持久化在会话上。
- **FR-002**: `icon` 会话中用户消息 MUST 先由文本图标 Agent 处理（反向拷问），MUST NOT 在确认或显式跳过前调用生图模型。
- **FR-003**: 图标 Agent 每轮澄清 MUST 约 2–4 个相关点，SHOULD 附带建议提示词草案，并 MUST 推进或确认目标尺寸列表。
- **FR-004**: 用户确认或跳过澄清后，系统 MUST 按敲定尺寸列表一次性批量生成位图图标（每尺寸至少一档输出）。
- **FR-005**: 图标产出 MUST 为位图格式（PNG 和/或 WebP）；MVP MUST NOT 要求 SVG 矢量输出。
- **FR-006**: 系统 SHOULD 在提示词与生成参数中优先请求透明背景；无法保证时 MUST NOT 将失败伪装为透明成功。
- **FR-007**: 对话中的图标预览 MUST 支持点击收藏，行为与既有聊天图片收藏一致。
- **FR-008**: 资产元数据 MUST 区分类型（至少 `image` | `icon`）；资产库 MUST 提供类型过滤（全部 / 图片 / 图标）。
- **FR-009**: 本地二进制落盘 MUST 按 `会话ID / images|icons / …` 组织；本 feature 允许清空旧扁平数据，MUST NOT 以迁移旧文件为发布阻塞。
- **FR-010**: 图标 Agent 默认文本模型 MUST 与生图 Agent 一致策略（默认 `GPT-4o-Mini`，可环境变量覆盖）；生图模型仍走既有白名单/会话选择。
- **FR-011**: 系统 MUST 提供与生图 Agent 对等的「跳过澄清」「立即生成」能力（自然语言 + UI）。
- **FR-012**: MCP MUST 提供 `generate_icon`：直出批量图标、无反问；参数至少含提示词与可选尺寸列表/模型。
- **FR-013**: 密钥仍 MUST 仅从环境变量读取；错误 MUST NOT 回显密钥。
- **FR-014**: MVP MUST NOT 引入多用户认证、3D/骨骼、S3 上线或 SVG 生成管线。

### Key Entities

- **ConversationKind（会话用途）**: `image` | `icon`；决定 Agent 人格、默认澄清维度与落盘子目录。
- **IconSpec（图标规格）**: 建议提示词、透明底偏好、敲定的尺寸列表、可选风格/用途备注。
- **AssetType（资产类型）**: `image` | `icon`；用于过滤、展示与存储路径分支。
- **IconBatchJob（图标批量任务）**: 一次确认触发的多尺寸生成集合；含成功/失败分项结果。
- **McpIconCall（MCP 图标调用）**: 无澄清的直出请求；写入 MCP 来源会话与图标资产。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 图标会话在用户确认/跳过前，100% 不发起生图 API 调用（故意模糊提示的自测路径）。
- **SC-002**: 用户可在 5 分钟内完成「选图标会话 → 模糊需求 → 敲定尺寸 → 确认 → 看到多尺寸图标」演示（密钥有效时）。
- **SC-003**: 资产库类型过滤切换后，列表内容与所选类型一致（抽查 ≥10 条无错类）。
- **SC-004**: 新生成的图片与图标文件均落在对应会话的 `images` 或 `icons` 子目录下（手工或脚本检查）。
- **SC-005**: MCP `generate_icon` 在给定 2 个尺寸时返回成功资产且文件存在，端到端可在 2 分钟内验证。
- **SC-006**: 对话内收藏图标后，资产库在「图标 + 收藏」条件下可找到该资产。

## Assumptions

- 复用现有生图 Agent 的门闩交互模式与 Poe 位图生成能力；图标 Agent 为平行人格/系统提示，而非完全无关产品。
- 「尺寸列表由对话敲定」：Agent 可建议常用档（如 16/24/32/48/64/128/256/512），但最终以用户确认列表为准；跳过澄清时允许使用文档化默认集（建议 16/32/64）。
- 单尺寸过大请求上限在计划阶段给出具体数字（建议默认上限 12 档）。
- 透明背景依赖模型能力；规格要求「尽力请求」，不保证像素级 alpha 正确。
- WebP 与 PNG 的选择可在实现/计划中按模型返回 MIME 与透明需求决定；对用户只需可读预览与可下载文件。
- 清空 `data/` 为作者本机操作约定；产品无需提供花哨迁移 UI。
- MCP `list_image_models` 可继续共用；不必单独 `list_icon_models`，除非计划发现模型白名单需拆分。
- 中英 UI 跟随现有 i18n；图标相关文案补齐中英。
